# java-racingcar-precourse

## 주요 기능

### 1. 입력

* [x] **자동차 이름 입력:** 사용자로부터 쉼표(,)로 구분된 자동차 이름 입력받는 기능 구현.
* [x] **시도 횟수 입력:** 경주를 총 몇 라운드 진행할지 입력받는 기능 구현.
* [ ] **입력 유효성 검사:** 모든 사용자 입력에 대해 유효성 검사 구현. 다음과 같은 잘못된 입력의 경우 `IllegalArgumentException` 예외 발생:
    * [x] 비어 있는 자동차 이름일 경우.
    * [x] 이름이 글자 수 제한(5)을 초과할 경우.
    * [ ] 자동차 이름이 중복될 경우.
    * [x] 시도 횟수가 0 이하 또는 숫자가 아닌 경우.

### 2. 게임 로직

* [x] **무작위 전진:** 자동차 이동 핵심 로직 구현. 각 라운드마다 각 자동차에 대해 무작위 숫자(0-9)를 생성하고 이 숫자가 특정 기준(4 이상)을 만족하면 해당 자동차는 한 칸 앞으로 전진.
* [x] **라운드 진행 결과 출력:** 각 라운드 끝날 때마다 모든 자동차의 현재 위치를 출력하는 기능 구현.
* [x] **우승자 결정:** 모든 라운드 종료 후 가장 멀리 이동한 자동차 식별 로직 구현. 최대 이동 거리가 같은 경우 여러 명 우승 가능.

### 3. 출력

* [x] **최종 우승자 표시:** 경주가 끝난 후 최종 우승자 이름을 출력하는 기능 구현.
  * [x] **단일 우승자 표시:** 우승자가 한 명인 경우 단독으로 이름 출력.
  * [x] **복수 우승자 표시:** 우승자가 여러명인 경우 쉼표(,)로 구분하여 이름 출력.

### 개발 시 지켜야 할 것들
본 프로젝트 개발 시 특히 유의해야 할 주요 가이드라인을 정리한 내용

* **들여쓰기(Indent) 깊이 제한:**
  * 함수(메서드) 내에서 코드 들여쓰기는 최대 2단계까지만 허용.
  * 들여쓰기 깊이를 줄이기 위해 함수(메서드)를 적극적으로 분리.

* **삼항 연산자 사용 금지:**
  * 가독성을 위해 삼항 연산자 사용을 지양.

* **함수/메서드 최소화:**
  * 함수(메서드)는 한 가지 책임만 갖도록 최대한 작게 구현.

* **테스트 코드 작성:**
  * 구현된 기능 목록이 정상적으로 작동하는지 JUnit 5와 AssertJ를 사용하여 테스트 코드를 작성하고 검증.

* **Java API 적극 활용:**
  * 기능 구현 전, Java 표준 API에서 제공하는 기능인지 먼저 확인하고 적극적으로 활용. (예: `String.join()`, `List.contains()` 등)

* **컬렉션 사용:**
  * 데이터 구조는 특별한 이유가 없는 한 배열 대신 컬렉션(`List`, `Set`, `Map` 등)을 우선적으로 사용.
